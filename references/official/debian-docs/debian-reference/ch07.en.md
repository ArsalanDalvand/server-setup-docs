## 7.2.Â GUI communication protocol

GUI communication protocol used on the GNOME desktop can be:

[Wayland (display server protocol)](https://en.wikipedia.org/wiki/Wayland_(display_server_protocol)) (native)

[X Window System core protocol](https://en.wikipedia.org/wiki/X_Window_System_core_protocol) (via xwayland)

Please check [freedesktop.org site for how Wayland architecture is different from X Window architecture](https://wayland.freedesktop.org/architecture.html).

From user's perspective, differences can be colloquially summarized as:

Wayland is a same-host GUI communication protocol: new, simpler, faster, no setuid root binary

X Window is a network-capable GUI communication protocol: traditional, complex, slower, setuid root binary

For applications using Wayland protocol, the access to their display contents from a remote host is supported by the [VNC](https://en.wikipedia.org/wiki/Virtual_Network_Computing) or [RDP](https://en.wikipedia.org/wiki/Remote_Desktop_Protocol).  See [SectionÂ 7.8, âRemote desktopâ](ch07.en.md#_remote_desktop)

Modern X servers have [the MIT Shared Memory Extension](https://en.wikipedia.org/wiki/MIT-SHM) and communicate with their local X clients using the local shared memory.  This bypasses the network transparent [Xlib](https://en.wikipedia.org/wiki/Xlib) interprocess communication channel and gains performance.  This situation was the [background](https://wayland.freedesktop.org/faq.html) of creating Wayland as a local-only GUI communication protocol.

Using the xeyes program started from the GNOME terminal, you can check GUI communication protocol used by each GUI application.

```bash
$ xeyes
```

If the mouse cursor is on an application such as "GNOME terminal" which uses Wayland display server protocol, eyes don't move with the mouse cursor.

If the mouse cursor is on an application such as "xterm" which uses X Window System core protocol, eyes move with the mouse cursor exposing not-so-isolated nature of X Window architecture.

As of April 2021, many popular GUI applications such as GNOME and [LibreOffice (LO)](https://en.wikipedia.org/wiki/LibreOffice) applications have been migrated to the Wayland display server protocol.  I see xterm, gitk, chromium, firefox, gimp, dia, and KDE applications still use X Window System core protocol.

Note

For both the xwayland on Wayland or the native X Window System, the old X server configuration file "/etc/X11/xorg.conf" shouldn't exist on the system. The graphics and input devices are now configured by the kernel with [DRM](https://en.wikipedia.org/wiki/Direct_Rendering_Manager), [KMS](https://wiki.debian.org/KernelModesetting),  and [udev](https://en.wikipedia.org/wiki/Udev).  The native X server has been rewritten to use them.  See "[modedb default video mode support](https://www.kernel.org/doc/html/latest/fb/modedb.html)" in the Linux kernel documentation.

## 7.5.Â User directories

Default names for user directories such as "~/Desktop", "~/Documents", ..., used by the Desktop environment depend on the locale used for the system installation.  You can reset them to the English ones by:

```bash
$ LANGUAGE=C xdg-user-dirs-update --force
```

Then you manually move all the data to the newer directories.  See [xdg-user-dirs-update(1)](https://manpages.debian.org/unstable/xdg-user-dirs-update(1)).

You can also set them to any names by editing "~/.config/user-dirs.dirs".  See [user-dirs.dirs(5)](https://manpages.debian.org/unstable/user-dirs.dirs(5)).

## 7.6.Â Fonts

Many useful scalable fonts are available for users on Debian.  User's concern is how to avoid redundancy and how to configure parts of installed fonts to be disabled.  Otherwise, useless font choices may clutter your GUI application menus.

Debian system uses [FreeType](https://freetype.org) 2.0 library to rasterise many scalable font formats for screen and print:

[Type 1 (PostScript) fonts](https://en.wikipedia.org/wiki/PostScript_fonts#Type_1) which use cubic [BÃ©zier curves](https://en.wikipedia.org/wiki/BÃ©zier_curve) (almost obsolete format)

[TrueType fonts](https://en.wikipedia.org/wiki/TrueType) which use quadratic [BÃ©zier curves](https://en.wikipedia.org/wiki/BÃ©zier_curve) (good choice format)

[OpenType fonts](https://en.wikipedia.org/wiki/OpenType) which use cubic [BÃ©zier curves](https://en.wikipedia.org/wiki/BÃ©zier_curve) (best choice format)

### 7.9.1.Â X server local connection

Access to the local X server by the local applications which use X core protocol can be locally connected through a local UNIX domain socket.  This can be authorized by the authority file holding [access cookie](https://en.wikipedia.org/wiki/X_Window_authorization#Cookie-based_access). The authority file location is identified by the "$XAUTHORITY" environment variable and X display is identified by the "$DISPLAY" environment variable.  Since these are normally set automatically, no special action is needed, e.g. "gitk" as the following.

```bash
username $ gitk
```

Note

For xwayland, XAUTHORITY holds value like "/run/user/1000/.mutter-Xwaylandauth.YVSU30".

### 7.9.2.Â X server remote connection

Access to the local X server display from the remote applications which use X core protocol is supported by using the X11 forwarding feature.

Open an gnome-terminal on the local host.

Run [ssh(1)](https://manpages.debian.org/unstable/ssh(1)) with -X option to establish a connection with the remote site as the following.

```bash
localname @ localhost $ ssh -q -X loginname@remotehost.domain
Password:
```

Run an X application command, e.g. "gitk", on the remote site as the following.

```bash
loginname @ remotehost $ gitk
```

This method can display the output from a remote X client as if it were locally connected through a local UNIX domain socket.

See [SectionÂ 6.3, âThe remote access server and utilities (SSH)â](ch06.en.md#_the_remote_access_server_and_utilities_ssh) for SSH/SSHD.

Warning

A remote [TCP](https://en.wikipedia.org/wiki/Transmission_Control_Protocol)/[IP](https://en.wikipedia.org/wiki/Internet_Protocol) connection to the X server is disabled by default on the Debian system for security reasons.  Don't enable them by simply setting "xhost +" nor by enabling [XDMCP connection](https://en.wikipedia.org/wiki/X_display_manager), if you can avoid it.

### 7.9.3.Â X server chroot connection

Access to the X server by the applications which use X core protocol and run on the same host but in an environment such as chroot where the authority file is not accessible, can be authorized securely with xhost by using the [User-based access](https://en.wikipedia.org/wiki/X_Window_authorization#User-based_access), e.g. "gitk" as the following.

```bash
username $ xhost + si:localuser:root ; sudo chroot /path/to
# cd /src
# gitk
# exit
username $ xhost -
```
